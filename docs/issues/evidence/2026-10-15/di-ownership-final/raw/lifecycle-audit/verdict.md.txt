Three actionable findings:

1. **P1: Resolved contexts have two disposal owners.** [ServiceCollectionExtensions.cs:87](/home/dan/code/TurboTest/src/TurboTest.EFCore/Extensions/ServiceCollectionExtensions.cs:87) registers the lease’s raw context, which Microsoft DI captures separately. [TtFactory.cs:70](/home/dan/code/TurboTest/src/TurboTest.EFCore/TtFactory.cs:70) already retains its asynchronous cleanup. Scope disposal therefore invokes context disposal twice; overlapping provider disposal can invoke it concurrently. If DI’s first context disposal throws, DI skips `TtScopedLease`, leaving the lease reserved until provider shutdown. These ordering and failure behaviors follow the [pinned DI implementation](https://github.com/dotnet/runtime/blob/v10.0.9/src/libraries/Microsoft.Extensions.DependencyInjection/src/ServiceLookup/ServiceProviderEngineScope.cs). Existing lifetime tests never resolve the initialized context; native blocking tests use direct factory leases.

   Registering/resolving **`TtLease<TContext>`** is a faithful TT-007 contract. DI and the initialization wrapper then join the lease’s cached disposal job. Document the changed injection shape and update examples. I found no minimal supported way to retain arbitrary raw-context injection while guaranteeing exclusive cleanup.

2. **P1: Provider recovery exposes only the first failed owner.** [TtServiceFactory.cs:93](/home/dan/code/TurboTest/src/TurboTest.EFCore/TtServiceFactory.cs:93) and subsequent cleanup handling discard later exceptions and their cleanup capabilities. With two failed fixture drains, the documented captured-service recovery returns only the first capability, and repeated disposal returns that cached failure. Global retention prevents ownership loss, but provider-local recovery cannot join/retry every resource. Preserve an aggregate cleanup capability and assert recovery of two independently retained hosts.

3. **P2: Provider closure leaves later factories open temporarily.** [TtServiceFactory.cs:90](/home/dan/code/TurboTest/src/TurboTest.EFCore/TtServiceFactory.cs:90) closes owners sequentially. A blocked first owner lets an already-returned second factory accept leases during provider shutdown; multiple owners also multiply deadline waits. Initiate closure for all owners before awaiting any drain. Add a two-context oracle asserting immediate acquisition rejection and the intended provider deadline.
